## 测温原理：为什么观察衰减过程

荧光材料受到激励后产生发光响应；激励停止后，发光强度随时间衰减。对于适用的探头材料，在规定的工作区间内，衰减特征与温度之间存在可标定的关系。

测量链路先取得衰减信号，提取寿命特征，再依据标定关系换算温度。光强、背景和噪声影响信号是否可用，因此系统仍需要管理激励强度、采集量程和信号质量。

| 需要区分的量 | 在测量中的角色 |
|---|---|
| 信号强度 | 帮助判断是否过弱、饱和，以及光学连接是否合适 |
| 背景水平 | 影响衰减信号的提取，需要关注偏置及环境变化 |
| 荧光寿命特征 | 作为温度换算的输入，需要有效信号与合适的计算方法 |
| 标定关系 | 描述特定探头、条件与温度之间的对应关系 |
| 输出状态 | 告诉使用者当前温度是否可用、是否处于过渡或异常状态 |

寿命法关注的是衰减过程，但不意味着光路损耗、探头差异或模拟前端可以被忽略。具体性能需要结合探头、硬件、标定和验证条件评估。

## 系统如何协作

```mermaid
flowchart LR
  A[激励控制] --> B[光纤与荧光探头]
  B --> C[光电转换与模拟前端]
  C --> D[ADC / DMA 采集]
  D --> E[信号质量与寿命估计]
  E --> F[滤波与状态管理]
  F --> G[标定与温度换算]
  G --> H[Modbus RTU / 主机工具]
```

从系统角度，可以把一次测量理解为以下几个阶段：

1. **建立激励条件**：使探头产生可观测的响应，关注信号强度与量程。
2. **取得衰减过程**：围绕激励变化组织采集，区分所需信号与背景。
3. **判断信号可用性**：关注过弱、饱和、异常值和采集一致性。
4. **计算并管理结果**：提取寿命特征，处理波动、启动期和恢复过程。
5. **换算与对外输出**：结合标定关系产生温度，将结果及其状态交给主机。

实际工程中，采集、计算和通信可能并行发生；上述顺序用于理解模块关系。生产实现中的采样策略、窗口配置、计算细节与参数保留在私有工程中。

## 工程内容与技术价值

| 技术环节 | 需要解决的问题 | 完整工程的评估重点 |
|---|---|---|
| 激励与反馈控制 | 激励变化、信号强度与采集量程的协调 | 弱信号、饱和、连接变化时的行为 |
| 采集与时间组织 | ADC、DMA、定时事件和前台计算的配合 | 缓冲区数据来源、读取时刻与一致性 |

| 滤波与状态管理 | 在输出平稳和动态响应之间取舍 | 启动、过渡、无效输入与恢复 |
| 标定与换算 | 将特征值映射到温度 | 探头适用性、区间边界和参数版本 |
| 参数与持久化 | 管理运行配置及重启后的行为 | 更新、生效、保存和恢复的边界 |
| 通信与主机接入 | 让上层正确读取温度和状态 | 更新节奏、异常处理与操作边界 |
| 构建与验证 | 让工程能够被理解、复现和维护 | 工具版本、依赖、构建步骤与验证范围 |

交付的价值包括模块之间的关系、调试思路、工程约束和已有验证方法。换一个 MCU、探头或模拟前端，往往需要重新评估这些关系。

## 开发时容易忽略的四件事

**采样频率、结果更新频率和主机轮询频率不同。** 主机读取快，并不表示每次读到的都是新测量；底层采样快，也不意味着完整温度输出具有同样的更新速度。

**输出平稳与响应速度需要一起评价。** 滤波可以减小波动，也可能引入等待和延迟。评估时需要同时明确稳态表现与温度变化后的响应方式。

**温度值必须结合状态理解。** 启动、弱信号、连接异常和恢复过程中的结果，应通过约定的状态语义处理，不能只根据数值是否合理判断有效性。

**标定与目标探头、条件绑定。** 标定表不是脱离硬件和探头的通用附件。更换探头、调整光学结构或改变信号链后，需要确认原有标定关系是否仍适用。

更详细的说明见[工程设计要点](docs/engineering-notes.md)。
