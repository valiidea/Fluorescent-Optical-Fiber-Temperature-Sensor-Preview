# 接入与选型评估

本页帮助整理技术咨询所需的条件，不要求在公开 Issue 中提供私密资料。可以先说明大致平台和需求，再通过双方确认的私密渠道交流具体工程。

## 从已有条件开始

| 条件 | 需要确认的内容 | 对交付的影响 |
|---|---|---|
| 探头与光路 | 是否已有探头、连接方式、目标工作条件 | 决定信号特征及标定适用性是否需要重新评估 |
| 模拟前端 | 是否已有光电接收与信号调理硬件 | 决定量程、背景和采集接口的适配工作 |
| MCU 平台 | 芯片、存储资源、ADC/DMA 与定时资源 | 决定工程能否直接复用以及移植范围 |
| 通信接口 | 上位系统、物理接口与协议需求 | 决定通信接入和主机工具适配 |
| 目标性能 | 温区、更新需求、响应与可靠性要求 | 决定后续验证和交付验收的内容 |
| 开发环境 | 系统、工具链、调试方式和团队经验 | 决定构建说明及支持深度 |

## 三种常见接入起点

**已有相近平台，希望理解并修改工程。** 先确认硬件条件和版本对应关系，再约定源码、构建资料、模块说明及支持范围。

**已有探头和模拟前端，希望迁移到不同 MCU。** 需要评估外设能力、时序组织、数值计算、内存与通信环境。移植是否包含在报价中，应单独说明。

**只有目标场景，希望获得完整产品。** 应先明确是否需要硬件设计、探头、封装、认证或量产支持。当前技术交付不默认覆盖这些内容。

## 确认交付时的核对项

交付清单应能回答：提供哪些模块、适配哪个平台、依赖什么工具、哪些内容需要购买方自行准备、哪些行为已有验证、有哪些已知限制，以及遇到问题时如何获得约定支持。

技术匹配、商业使用范围和工程完成度需要分别确认。完整硬件设计、探头材料配方和母板固件不在默认交付范围内。
