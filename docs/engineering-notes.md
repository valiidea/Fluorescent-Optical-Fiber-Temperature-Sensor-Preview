# 工程设计要点

本页整理理解荧光光纤测温工程时值得关注的设计问题。它描述通用工程关系，不披露具体采样窗口、计算公式、算法常量或产品参数。

## 采集、计算与通信的时间关系

采集硬件产生数据，计算模块使用数据，通信模块对外提供结果。三个环节的节奏不一定相同，评估时需要分别回答：数据来自哪个测量阶段、计算使用哪一批数据、主机读到的结果何时产生。

DMA 可以减少处理器搬运数据的负担，但缓冲区仍可能在前台读取时变化。理解数据的所有权、更新时机及读取语义，是分析采集一致性的基础。具体实现采用怎样的同步方式，属于工程细节。

## 信号质量先于温度数值

| 现象 | 需要区分的问题 | 评估方向 |
|---|---|---|
| 信号过弱 | 光学连接、激励条件、探头响应或接收链路变化 | 是否还能取得可靠的衰减特征 |
| 信号饱和 | 激励、增益或量程不匹配 | 是否丢失了衰减形态 |
| 背景变化 | 偏置、杂散光或工作条件改变 | 背景与有效信号能否被区分 |
| 输出突然变化 | 真实温度变化、信号异常或状态切换 | 是否有足够上下文解释变化 |

这些是排查方向，不能仅凭单一现象确定原因。最终温度看起来合理，也不能替代对信号有效性的判断。

## 激励控制与测量并非彼此独立

改变激励条件可能改变信号强度和采集状态；而测量过程中看到的反馈又可能影响后续激励。理解这种相互影响，有助于解释调节过程、等待时间和恢复行为。

评估一套实现时，应关注调节前后的数据如何被使用、何时允许重新发布有效结果，以及异常条件下的边界。具体闭环策略和参数不在公开预览中展开。

## 滤波需要兼顾时间成本

平滑程度、启动等待、动态响应和异常恢复是同一个结果处理链中的不同侧面。更强的平滑可能带来更长的响应时间；异常输入是否进入历史数据，也会影响后续输出。

因此，评估滤波不宜只看稳态波动，还应明确温度变化后的响应、启动期状态和恢复条件。本页不指定滤波类型、窗口长度或判定阈值。

## 标定需要保留适用条件

标定应关联探头、硬件配置、参考条件、适用区间与参数版本。参数被正确载入，与参数在当前工况下仍然适用，是两件需要分别验证的事。

区间内换算、区间外处理、无效参数及参数更新后的行为，都应纳入交付说明。购买已有标定实现，也需要确认自己的探头和信号链是否满足使用条件。

## 状态与持久化是接入的一部分

上层系统需要知道什么是有效温度、何时处于启动或恢复阶段、发生异常后应该等待还是报告故障。状态含义应与通信文档一致。

运行参数的修改、保存、生效和重启恢复也需要清晰边界。通信返回成功、运行参数发生变化和掉电后仍然保留，不应被自动视为同一件事。

## 如何用这些内容评估技术交付

在确认交付前，将关注的问题映射到具体资料：模块说明、构建方法、配置说明、接口文档、已知限制及约定的验证步骤。这样才能判断购买的是哪些可用能力，以及后续还需要哪些适配工作。
