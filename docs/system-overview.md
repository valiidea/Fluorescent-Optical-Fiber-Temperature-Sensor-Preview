# 测温链路与模块职责

荧光光纤测温的工程任务，是把一次光学响应转化为可解释、可校准、可稳定读取的温度结果。本页讲解模块之间的关系，便于评估开发工作量。

```mermaid
flowchart LR
  A[激励控制] --> B[光纤与荧光探头]
  B --> C[光电转换与模拟前端]
  C --> D[ADC / DMA 采集]
  D --> E[信号质量与寿命估计]
  E --> F[滤波与状态管理]
  F --> G[标定换算]
  G --> H[温度与状态输出]
  H --> I[Modbus RTU / 主机记录]
```

## 每个模块解决什么问题

| 模块 | 作用 | 开发时要验证的事情 |
|---|---|---|
| 激励与光学链路 | 激发探头并接收返回信号 | 信号强度、饱和、连接变化及激励一致性 |
| 模拟前端与采集 | 将连续信号变成数字序列 | 背景、量程、噪声、采样时序和缓冲区一致性 |
| 寿命估计 | 从衰减过程得到与温度有关的特征 | 信号是否有效、异常输入、不同信噪比下的表现 |
| 滤波与状态 | 减小波动并表达数据是否可用 | 平滑程度与响应延迟、启动期和故障恢复 |
| 标定换算 | 建立特征值与温度的对应关系 | 参考温度、探头个体差异、适用区间和越界行为 |
| 通信与记录 | 把温度、状态和上下文交给主机 | 编码、通信失败、更新时间与记录完整性 |

这些模块不能彼此脱离地评价。例如，输出曲线很平滑可能来自较强的滤波；只有同时观察温度阶跃响应，才能判断平滑是否付出了过大的延迟代价。

## 三个容易混淆的概念

**采样频率、结果更新频率、主机轮询频率**是不同的时间尺度。每秒记录一次温度，并不表示底层每秒只测量一次；也不能从一秒一条的记录恢复每个内部周期的行为。

**背景、信号强度、衰减特征**承担不同角色。背景变化可能污染衰减观测，信号过弱或饱和则会降低可用性。技术评估应同时关注信号质量和算法输出，不能仅看最终温度是否“像是正常”。

**稳定性、重复性、准确度**需要不同证据。短时间波动统计衡量这段输出的变化；重复性需要重复实验；准确度需要可信参考及对应的实验条件。
